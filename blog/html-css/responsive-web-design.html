Responsive Web Design Using CSS

By SP Siam Ahmed · Published 26 November 2026 · Updated 26 November 2026

Table of Contents

  • Media Queries That Make Sense
  • Responsive Typography
  • Responsive Images and Media

Responsive web design means a website works well on every screen — a 320px phone, a tablet, a laptop and a wide desktop — from a single codebase. It is not a feature you add at the end; it is how the site is built from the first line of CSS.

Start Mobile-First

Write your base CSS for the smallest screen first, then add complexity for larger screens with min-width media queries. This keeps the mobile experience fast and simple, and it matches how most people actually browse: mobile traffic is the majority of web traffic in most countries, including Bangladesh.

Mobile-first also forces good decisions. If a section works on a 360px screen, it almost always works everywhere else. The reverse is not true.

Fluid Layouts

Avoid fixed pixel widths for layout containers. Use percentages, fr units in Grid, flexible Flexbox items, and a max-width with automatic margins to centre content:

.container {
  width: 100%;
  max-width: 1120px;
  margin: 0 auto;
  padding: 0 20px;
}

.grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: 20px;
}

@media (min-width: 768px) {
  .grid { grid-template-columns: repeat(2, 1fr); }
}

@media (min-width: 1024px) {
  .grid { grid-template-columns: repeat(3, 1fr); }
}

Media Queries That Make Sense

Choose breakpoints where your design actually breaks, not by device brand. Common, practical breakpoints are around 576px, 768px, 1024px and 1280px. A layout that switches from one column to two at 768px and to three at 1024px covers phones, tablets and desktops cleanly.

Inside a media query, change as little as possible — usually just the number of columns, the font size and the spacing. If a query rewrites half the page, the base design probably needs rethinking.

Responsive Typography

Use clamp() so headings scale smoothly instead of jumping between sizes:

h1 {
  font-size: clamp(2rem, 5vw, 3.4rem);
}

h2 {
  font-size: clamp(1.5rem, 3.5vw, 2.2rem);
}

clamp(minimum, preferred, maximum) guarantees the text never gets smaller than the minimum or larger than the maximum, while scaling with the viewport in between. Body text can stay at a comfortable 16px — never smaller, for readability.

Responsive Images and Media

Images are the most common cause of horizontal scrolling. Two rules fix most of it:

img, video {
  max-width: 100%;
  height: auto;
}

body { overflow-x: hidden; }

Also set width and height attributes on images so the browser reserves space before they load — that prevents layout shift, which is one of the Core Web Vitals. Add loading="lazy" to images below the fold.

Testing on Real Sizes

Test at 320px, 360px, 375px, 768px, 1024px and 1440px at minimum. Check for horizontal scrolling, overlapping text, clipped headings and buttons that are too small to tap (aim for at least 44px of touch target). Browser developer tools can emulate these sizes, but nothing replaces opening the site on a real phone at least once.

Google also indexes the mobile version of your site first — mobile-first indexing — so a broken mobile layout is also an SEO problem. The Google SEO Starter Guide covers mobile-friendliness as a core requirement.

Conclusion

Responsive design is a discipline, not a trick: mobile-first CSS, fluid layouts, sensible breakpoints, clamp() typography, responsive images and real testing. Build that way from the start and your site will feel right on every device your visitors use.
