How to Host a Website on GitHub Pages

By SP Siam Ahmed · Published 26 November 2026 · Updated 26 November 2026

Table of Contents

  • Create the Repository
  • Add Your Files
  • Enable GitHub Pages
  • Updating Your Site
  • Limits to Know
  • Conclusion

GitHub Pages is a free hosting service that publishes a static website straight from a GitHub repository. If your site is HTML, CSS and JavaScript — like this one — you can have it live on the public internet in about ten minutes, with no server to manage and no hosting bill.

What Is GitHub Pages?

GitHub Pages takes the files in a repository and serves them as a website. Every push you make updates the live site automatically. It supports plain HTML/CSS/JavaScript, Jekyll, and any static site generator whose output is HTML. It does not run server-side code — no PHP, no Node.js, no databases — which is exactly why it is simple and reliable.

Your site gets an address like https://username.github.io/repository/, or https://username.github.io/ for a special repository named username.github.io. You can also connect your own domain, covered in How to Connect a Custom Domain to GitHub Pages.

Before You Start

You need a GitHub account and Git installed on your computer. Your website files should be ready in a folder: an index.html at the root, plus your CSS, JavaScript and images. Test the site locally first — open index.html in a browser, or serve the folder with a simple local server — so you know it works before you publish it.

Create the Repository

On GitHub, create a new repository. For a project site, any name works — for example my-portfolio. For a personal site at username.github.io, the repository must be named exactly username.github.io. Make it public; GitHub Pages on the free plan serves public repositories.

Add Your Files

Push your files to the repository with Git:

git init
git add .
git commit -m "First version of my website"
git branch -M main
git remote add origin https://github.com/username/my-portfolio.git
git push -u origin main

Replace username and my-portfolio with your own values. If you prefer not to use the command line, you can upload the files through the GitHub website instead — the result is the same.

Enable GitHub Pages

Go to the repository on GitHub, open Settings, then Pages in the left sidebar. Under Build and deployment, choose Deploy from a branch, select the main branch and the / (root) folder, and save. GitHub will build your site — usually within a minute or two — and show you the live URL at the top of the same page.

The official documentation at GitHub Pages covers every option, including deploying from a /docs folder or from a GitHub Actions workflow.

Updating Your Site

To update the live site, change the files, commit and push. GitHub rebuilds and redeploys automatically — there is nothing else to do. If a change does not appear straight away, wait a minute and hard-refresh your browser (Ctrl+Shift+R or Cmd+Shift+R), because browsers cache pages aggressively.

Limits to Know

  • Static only: no server-side code, no databases, no form processing. A contact form needs a form service, or a mailto link like the one on this site.
  • Size: repositories have a recommended limit of 1 GB, and individual files should stay under 100 MB.
  • Bandwidth: the free soft limit is 100 GB of bandwidth per month — far more than a personal site normally uses.

Conclusion

GitHub Pages is the fastest honest route from files on your computer to a live website: create a repository, push your files, enable Pages, and share the link. It is free, it deploys on every push, and it is how many developers — including me — host their portfolios.
