How to Connect a Custom Domain to GitHub Pages

By SP Siam Ahmed · Published 26 November 2026 · Updated 26 November 2026

Table of Contents

  • What You Need
  • Add the CNAME File
  • Set the DNS Records
  • Enable HTTPS
  • Common Problems
  • Conclusion

A custom domain turns username.github.io into your own address — siam.dev, for example. The setup has two parts: telling GitHub which domain to answer for, and telling the domain where to point. Both are simple, and both are covered here.

What You Need

You need a website already live on GitHub Pages (see How to Host a Website on GitHub Pages) and a domain you own, bought from any registrar. You also need access to your registrar's DNS settings — that is where the records are edited.

Add the CNAME File

Create a file named CNAME (no extension) in the root of your repository — the same folder as your index.html — containing exactly one line: your domain name.

siam.dev

That file tells GitHub Pages: this repository serves this domain. Alternatively, open the repository's Settings → Pages and type the domain into the Custom domain field; GitHub creates the CNAME file for you. Either way, commit and push, and wait a few minutes.

Set the DNS Records

At your domain registrar, add the DNS records that point your domain to GitHub Pages. For an apex domain (a domain without www, like siam.dev), add four A records pointing to GitHub Pages' IP addresses:

185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153

For the www subdomain, add a CNAME record pointing www to username.github.io (replace username with your GitHub username). DNS changes can take anywhere from a few minutes to 24 hours to spread around the world, so be patient — and check with your registrar's own DNS checker rather than guessing.

The exact IP addresses and the full procedure are documented in GitHub Pages documentation. If GitHub ever changes its addresses, that page is the source of truth — do not copy IP addresses from a random blog post, including this one, without verifying them there.

Enable HTTPS

Once GitHub detects the correct DNS records, the Enforce HTTPS checkbox appears in Settings → Pages. Tick it. GitHub issues a free certificate automatically, and your site will load over HTTPS. If the checkbox is greyed out, the DNS has not propagated yet — wait and check again later.

Common Problems

  • Site shows a 404: the CNAME file is missing, misspelled, or in the wrong folder. It must be at the repository root.
  • Domain points nowhere: the DNS records are wrong or have not propagated yet. Double-check the A records and the www CNAME.
  • Certificate errors: HTTPS cannot be enabled until DNS is correct, and it can take up to 24 hours after that.
  • Old content showing: browsers cache aggressively. Hard-refresh, or test in a private window.

Conclusion

A custom domain is a small amount of work for a large amount of professionalism: one CNAME file, four A records, one www CNAME, and HTTPS switched on. Your portfolio stops looking like a demo and starts looking like a home on the web — which is exactly what it is.
