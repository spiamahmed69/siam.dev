Image Optimization for Faster Websites

By SP Siam Ahmed · Published 26 November 2026 · Updated 26 November 2026

Table of Contents

  • Use Modern Formats
  • Compress Without Visible Loss
  • Lazy Loading
  • Dimensions and Layout Shift
  • Conclusion

Images are usually the heaviest part of a web page. A single unoptimised photo can weigh more than all of your HTML, CSS and JavaScript combined — and it is the most common reason a page loads slowly. The good news: image optimisation is also one of the easiest performance wins there is.

Why Images Matter Most

On a typical page, images account for roughly half the total bytes. That affects everything: the time to first paint, the Largest Contentful Paint (see Core Web Vitals Explained), mobile data usage, and the experience of visitors on slow connections. Optimising images is often the single biggest improvement you can make to a slow site, and it takes minutes.

Serve the Right Size

Never serve a 4000px photo to display it at 400px. Resize images to the largest size they will actually be shown at — and if the same image appears at several sizes, generate several versions and let the browser choose with srcset:

<img src="photo-800.jpg"
     srcset="photo-400.jpg 400w,
             photo-800.jpg 800w,
             photo-1200.jpg 1200w"
     sizes="(max-width: 600px) 400px, 800px"
     width="800" height="600"
     alt="A description of the photo">

The browser picks the smallest file that still looks sharp on the visitor's screen. On a phone it downloads the 400px version; on a desktop, the 800px or 1200px version. Nobody downloads more than they need.

Use Modern Formats

WebP and AVIF compress far better than JPEG and PNG for the same visual quality — typically 25–35% smaller for WebP, and more for AVIF. Use WebP as the default today; it is supported by every modern browser. Keep PNG only for images that need transparency or pixel-perfect edges, such as logos and diagrams, and keep JPEG as a fallback where WebP is not available.

For simple graphics — icons, logos, illustrations — consider SVG instead. SVG is a vector format, so it stays sharp at any size and is often only a few kilobytes. This site's cover art and profile image are SVG for exactly that reason.

Compress Without Visible Loss

Compression tools remove data the eye cannot see. A photo exported at 80% JPEG quality usually looks identical to the original at a fraction of the size. Free tools like Squoosh (from Google) let you compare before and after side by side — aim for the smallest file where you cannot tell the difference.

As a rule of thumb: a hero image should be under 200 KB, a normal content image under 100 KB, and a thumbnail under 30 KB. If an image is bigger than that, it can almost always be smaller.

Lazy Loading

Images below the fold do not need to load before the visitor scrolls to them. Add loading="lazy" and the browser defers them automatically:

<!-- Load immediately: hero image -->
<img src="hero.jpg" alt="Hero image" fetchpriority="high">

<!-- Load when scrolled to: everything else -->
<img src="photo.jpg" alt="Content photo" loading="lazy">

Do not lazy-load the hero image — that delays the Largest Contentful Paint. Everything else can wait until it is needed. This one attribute can cut the initial page weight in half on image-heavy pages.

Dimensions and Layout Shift

Always set width and height attributes on images. The browser then reserves the right amount of space before the image loads, so the text below it does not jump when the image arrives. That single habit fixes most Cumulative Layout Shift problems — see Core Web Vitals Explained for why that score matters.

Conclusion

Image optimisation is five habits: right-size every image, use WebP (or SVG for graphics), compress sensibly, lazy-load everything below the fold, and always set dimensions. Do those five and your pages will load noticeably faster — on every device, on every connection — with no visible difference in quality. Measure the result with PageSpeed Insights and enjoy the improvement.
